Second occurrence of the same root cause — worth finding out what's spawning these unmanaged copies (manual `node server.js` runs left in a terminal / tmux session?) rather than just killing it again next time.
- 2026-08-15: Cole thought he'd accidentally **deleted** card #286 (Charles Leclerc, Topps Awards) — it wasn't deleted, editing it had silently wiped its `set_name` to blank, so it vanished from set-filtered admin views. **Root cause found and fixed**: the edit form's Set dropdown (`views/admin/card-edit.ejs`) is `disabled` by design and only re-enabled by JS after matching the card's manufacturer to a set list fetched from a separate API. When that match fails, the field ends up enabled-but-empty, submits `set_name=` on save, and `routes/admin.js` explicitly nulls empty strings for that field. Any edit to an affected card (price, quantity, anything) could silently blank its set. Fixed by making `POST /cards/:id/edit` delete `set_name` from the update payload entirely — that field should never be writable from this form. Recovered card 577's data from the 2026-08-14 nightly backup (`/mnt/storage/backups/trulycollectables/`) to confirm/restore it. This is very likely the same root cause behind the ~27 cards found earlier tonight with blank `set_name` (Leclerc Signature Style, several Lawson cards, etc.) — those were probably edited at some point via this same broken path, not bad import data as first assumed.
