Fixed: killed the orphan, pm2 took over the port cleanly.

- 2026-08-16: **CSP was blocking all `onclick` handlers site-wide** — Helmet 7 defaults `script-src-attr` to `'none'`, silently blocking every inline event attribute (`onclick`, etc.) across every page. Set checklist filter tabs, card toggles, and other onclick-driven interactions were all non-functional. Fixed by adding `scriptSrcAttr: ["'unsafe-inline'"]` to the Helmet config in `middleware/security.js`. Primary user device is a tablet.
- 2026-08-16: Fixed set checklist UX — card toggle in "Missing" filter now delays `applyFilters()` by 900ms so the green checkmark is visible before the card disappears from view. Collection add search results now use AJAX (stay on page, button turns green "Added") instead of navigating away on form submit.
- 2026-08-15: Hit the **same orphaned-process bug as 2026-07-31 again** — an unmanaged `node server.js` (running since Aug 12, 3 days) was squatting on port 3010, blocking pm2's restart with EADDRINUSE. Killed the orphan, pm2 back to clean `online` status. Second occurrence of the same root cause — worth finding out what's spawning these unmanaged copies (manual `node server.js` runs left in a terminal / tmux session?) rather than just killing it again next time.
- 2026-08-15: Cole thought he'd accidentally **deleted** card #286 (Charles Leclerc, Topps Awards) — it wasn't deleted, editing it had silently wiped its `set_name` to blank, so it vanished from set-filtered admin views. **Root cause found and fixed**: the edit form's Set dropdown (`views/admin/card-edit.ejs`) is `disabled` by design and only re-enabled by JS after matching the card's manufacturer to a set list fetched from a separate API. When that match fails, the field ends up enabled-but-empty, submits `set_name=` on save, and `routes/admin.js` explicitly nulls empty strings for that field. Any edit to an affected card (price, quantity, anything) could silently blank its set. Fixed by making `POST /cards/:id/edit` delete `set_name` from the update payload entirely — that field should never be writable from this form. Recovered card 577's data from the 2026-08-14 nightly backup (`/mnt/storage/backups/trulycollectables/`) to confirm/restore it. This is very likely the same root cause behind the ~27 cards found earlier tonight with blank `set_name` (Leclerc Signature Style, several Lawson cards, etc.) — those were probably edited at some point via this same broken path, not bad import data as first assumed.
